## Rules
- **Role**: read it from `~/.config/chezmoi/chezmoi.toml` (`[data] role`, written by `chezmoi init` from `home/.chezmoi.toml.tmpl`, which asks for it with `promptChoiceOnce`) — never add hostname checks or other guessing. Its prompt text is repeated in `Bootstrap.ps1` (`-Role`) and the CI `chezmoi` job's `--promptChoice`; keep them in sync. chezmoi templates use `.role`; the pre-commit hook reads the toml file; `Scripts/Setup` scripts get `-Role` from their chezmoi trigger. Anything work-only goes in the overlay (age-encrypted files, listed in `home/.chezmoiignore`, or the `*.work` plain-text lists) — no untracked machine-local files, apart from what apps and tools write for one machine (gitignored UniGetUI state, `~/.gitconfig`).
- **New optional component**: a `promptBoolOnce` in `.chezmoi.toml.tmpl`, a switch in `Bootstrap.ps1` (same prompt text) and in the setup script, the answer in the CI `chezmoi` job's `--promptBool` list and in `Test-Bootstrap.ps1`. In a trigger, read a key machines may not have yet as `{{ and (hasKey . "name") .name }}` (they get it on their next `chezmoi init`).
- **Symlink mode (Windows)**: plain files in `home/` are symlinked into place, so apps write straight into the repo. Templates (`.tmpl`) and encrypted files are copies — so never make an app-written file a template; put machine differences in the overlay or in a layer the app supports (git includeIf, profile dot-source, VS Code workspace settings). WSL uses `mode = "file"` (copies); an app-written file WSL shares must be a `symlink_*.tmpl` entry pointing into `Config/` (as Claude Code's settings are).
- **Never hard-code `Documents\...`**: the work machine's Documents folder is in OneDrive. `$PROFILE` is a stub written at run time by `Scripts/Setup/Set-MachineLinks.ps1`.
- **WSL**: `.chezmoiignore` drops `AppData`, `.config/powershell` and the work overlay there. The `.ps1` triggers are wrapped in `{{ if eq .chezmoi.os "windows" }}` (an empty script is skipped); WSL's own trigger is `run_onchange_after_20-packages-wsl.sh.tmpl`. The Windows-only prompts in `.chezmoi.toml.tmpl` aren't asked on Linux.
- **Scripts**: logic in `Scripts/Setup/*.ps1` (linted); the `home/.chezmoiscripts/*.tmpl` files only pass data (`-Role`, switches) and embed `sha256sum` hashes of the inputs that should re-trigger them. A script's non-zero exit makes chezmoi report it and retry on the next apply.
- **Testing chezmoi changes without touching the machine**: `chezmoi status --exclude=scripts` / `chezmoi diff` (read-only; `status` and `verify` always report the `run_after_` script, so exclude scripts to check files and links), `chezmoi execute-template < file.tmpl` for one template, or isolated: `chezmoi init --source . --config=<tmp>\c.toml --destination=<tmp>\home --persistent-state=<tmp>\s.boltdb --promptBool "<prompt text>=true,..."` then `chezmoi apply --dry-run --exclude=encrypted` with the same flags (what the CI `chezmoi` job does). `--promptBool` keys are the prompt texts, not the data keys; always pass `--no-tty` when running non-interactively, or chezmoi waits for input.
- **Pre-commit hook**: runs in Windows PowerShell 5.1 (via `powershell.exe`), NOT pwsh 7. Avoid PS7-only syntax (e.g. `?.`) and non-ASCII characters (5.1 reads BOM-less files in the system code page) in GitHooks scripts; CI checks both. `Scripts/Setup` and `Bootstrap.ps1` run under pwsh 7.
- **Gitignored UniGetUI files**: `CurrentSessionToken`, `OperationHistory(.json)`, `WindowGeometry`, `TelemetryClientToken`, `IpcApiEndpoints/`, `MaintenanceTaskLastRun.json`, `KnownLocalBackupNames.json`, `ChangeBackupOutputDirectory`, one-time flags `AlreadyWarnedAboutAdmin`, `AutoUpdatedPackagesImported`, and UI state/per-machine lists `SidepanelWidths.json`, `HideToggleFilters.json`, `WinGetAlreadyUpgradedPackages.json`, `WinGetUpgradeAttempts.json`, `LastKnownBuildNumber` — runtime state; inside the linked folder, gitignored = machine-local. UniGetUI's package backups are off (no `EnablePackageBackup` file): the WinGet lists replace them.
- **mssql connections** (and their connection groups): never in the shared VS Code settings (work server names/IPs, public repo). They belong in `~/work.code-workspace` (overlay; save with `chezmoi add --encrypt ~/work.code-workspace`). The pre-commit hook and the `leaks` CI job both catch the connections key; the CI check also catches private IP addresses anywhere — when mentioning the key in docs, don't write it as a quoted JSON key.
- **Git config**: context-specific settings go in their own file in `home/dot_config/git/`, pulled in by a condition in `config`. Relative include paths resolve next to `~/.config/git/config`. Never use `git config --global` to change a shared setting: it writes to `~/.gitconfig` (`create_dot_gitconfig`: created once, per machine, read last); edit `home/dot_config/git/config` instead. `core.pager = delta` is shared, so delta must be installed wherever the config goes (WinGet base list, `git-delta` in WSL).
- **PowerToys settings**: the `App` entry is merged, so it may be partial; any other module's entry must be the full `settings` object from `PowerToys.DSC.exe get --module <Name> --resource settings`. PowerToys' PowerShell DSC module is broken in 0.101 (compares DisplayVersion `0.101.2362` to the registry's `0.101.2362.0`), so it isn't used from the WinGet list.
- **PowerShell modules**: PSResourceGet (`Install-PSResource`, `Get-InstalledPSResource`), not PowerShellGet v2 — `Get-InstalledModule` misses versions it didn't install itself. Updates come from UniGetUI; the setup only installs missing ones and removes superseded versions.
- **Profile startup is tuned** (see comments in `user_profile.ps1`): nothing before the first prompt may use cmdlets from Microsoft.PowerShell.Management/Utility (`Get-Item`, `Test-Path`, `Set-Alias`, `Register-EngineEvent`, ...) — use .NET/engine APIs instead; modules load lazily on first use; oh-my-posh/zoxide init scripts are cached and patched in `%LOCALAPPDATA%\PowerShellProfileCache` (bump the `v6` cache key after changing a `$Generate` block). The patches measurably help (about 300 ms at startup, 30 ms per prompt); a first-prompt prefetch was measured, gained nothing and was removed. Never set `Set-PSReadLineOption -EditMode` below custom key bindings — it resets them. New aliases: a `${alias:name} = 'target'` line in the `#Alias` section, not `Set-Alias`. The `cheat` function is the one list of shortcuts.
- **Elevation**: `Bootstrap.ps1` runs everything elevated; per-user tools downloaded and executed as scripts (the Claude Code installer) go through `Invoke-Unelevated` in `Install-Packages.ps1` (a scheduled task with RunLevel Limited). Bootstrap only pauses at the end in the window it relaunched itself into (`-Relaunched`).
- **User PATH edits**: `HKCU:\Environment\Path` is `REG_EXPAND_SZ` and contains `%USERPROFILE%`, `%NVM_HOME%` and `%NVM_SYMLINK%` tokens. Write it with `Set-ItemProperty -Type ExpandString` and read it with `GetValue('Path','','DoNotExpandEnvironmentNames')`. `[Environment]::SetEnvironmentVariable(...,'User')` expands those tokens and bakes them out permanently, breaking the nvm indirection.
- **CI pins**: actions by SHA (Dependabot bumps them); chezmoi (version + release checksums) and PSScriptAnalyzer in `lint.yml` are bumped by hand.
