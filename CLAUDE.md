## Rules
- **Role**: read it from `~/.config/chezmoi/chezmoi.toml` (`[data] role`, written by `chezmoi init` from `home/.chezmoi.toml.tmpl`, which asks for it with `promptChoiceOnce`) — never add hostname checks or other guessing. Its prompt text is repeated in `Bootstrap.ps1` (`-Role`) and the CI `chezmoi` job's `--promptChoice`; keep them in sync. chezmoi templates use `.role`; the pre-commit hook reads the toml file; `Scripts/Setup` scripts get `-Role` from their chezmoi trigger. Anything work-only goes in the overlay (age-encrypted files, listed in `home/.chezmoiignore`, or the plain-text work lists) — no untracked machine-local files, apart from what apps and tools write for one machine (UniGetUI's runtime state, `~/.gitconfig`).
- **What a machine installs follows its role**: a package goes in `Config/WinGet/configuration.dsc.yaml` (every machine) or `configuration.<role>.dsc.yaml`, with an update source in UniGetUI (README: Package Updates; CI checks it) — not behind a new prompt. A prompt is only for a per-machine value (the Dev Drive): a `promptStringOnce` with a default that means "none" (no commas in the prompt text: `--promptString` splits on them), a string parameter in `Bootstrap.ps1` and the answer in the CI job's `--promptString`; Test-Bootstrap passes `none`, as Windows PowerShell 5.1 drops empty arguments to native commands. In a trigger, read a key machines may not have yet as `{{ and (hasKey . "name") .name }}` (they get it on their next `chezmoi init`).
- **Symlink mode (Windows)**: plain files in `home/` are symlinked into place, so apps write straight into the repo. Templates (`.tmpl`) and encrypted files are copies — so never make an app-written file a template; put machine differences in the overlay or in a layer the app supports (git includeIf, profile dot-source, VS Code workspace settings). WSL uses `mode = "file"` (copies); an app-written file WSL shares must be a `symlink_*.tmpl` entry pointing into `Config/` (as Claude Code's settings are).
- **Never hard-code `Documents\...`**: the work machine's Documents folder is in OneDrive.
- **WSL**: `.chezmoiignore` drops `AppData`, `.config/powershell` and the work overlay there. The `.ps1` triggers are wrapped in `{{ if eq .chezmoi.os "windows" }}` (an empty script is skipped); WSL's own trigger is `run_onchange_after_20-packages-wsl.sh.tmpl`. The Dev Drive prompt in `.chezmoi.toml.tmpl` isn't asked on Linux.
- **Scripts**: logic in `Scripts/Setup/*.ps1` (linted); the `home/.chezmoiscripts/*.tmpl` files only pass data (`-Role`, `-DevDrive`) and embed `sha256sum` hashes of the inputs that should re-trigger them, the script itself included. Each wraps its call in `try { & '...' } catch { Write-Error $_; exit 1 }`: a call that fails before the script runs (a parameter binding error) leaves `$LASTEXITCODE` unset and would exit 0. A script's non-zero exit makes chezmoi report it and retry on the next apply. A `run_onchange_` script doesn't run again for content it has run before (chezmoi keeps every hash), so a setting that can go back to an earlier value is applied by a cheap `run_after_` script on every apply (the Dev Drive).
- **Testing chezmoi changes without touching the machine**: `chezmoi status --exclude=scripts` / `chezmoi diff` (read-only; `status` and `verify` always report the `run_after_` scripts, so exclude scripts to check files and links), `chezmoi execute-template < file.tmpl` for one template, or isolated: `chezmoi init --no-tty --source . --config=<tmp>\c.toml --destination=<tmp>\home --persistent-state=<tmp>\s.boltdb --promptChoice "Machine role (work adds the encrypted work overlay)=private" --promptString "Dev Drive for the package caches (a drive like D: or none)=none"` then `chezmoi apply --no-tty --dry-run --exclude=encrypted` with the same flags (what the CI `chezmoi` job does). The `--prompt*` keys are the prompt texts, not the data keys; always pass `--no-tty` when running non-interactively, or chezmoi waits for input.
- **UniGetUI**: `.gitignore` allowlists the shared settings in `Config/UniGetUI`, so new runtime state stays on its machine; to share a new setting, add its `!` line. Package backups are off (no `EnablePackageBackup` file): the WinGet lists replace them.
- **mssql connections** (and their connection groups): never in the shared VS Code settings (work server names/IPs, public repo). They belong in `~/work.code-workspace` (overlay; save with `chezmoi add --encrypt ~/work.code-workspace`). The pre-commit hook and the `leaks` CI job both catch the connections and connection-groups keys; the CI check also catches private IP addresses anywhere — when mentioning the key in docs, don't write it as a quoted JSON key.
- **Git config**: never `git config --global` for a shared setting (it lands in the per-machine `~/.gitconfig`); edit `home/dot_config/git/config`. Relative include paths resolve next to `~/.config/git/config`. `core.pager = delta` is shared, so delta must be installed wherever the config goes (WinGet base list, `git-delta` in WSL).
- **PowerShell modules**: PSResourceGet (`Install-PSResource`, `Get-InstalledPSResource`), not PowerShellGet v2 — it is much faster, and `Get-InstalledModule` misses versions it didn't install itself.
- **Profile startup is tuned** (see comments in `user_profile.ps1`): nothing before the first prompt may use cmdlets from Microsoft.PowerShell.Management/Utility (`Get-Item`, `Test-Path`, `Set-Alias`, `Register-EngineEvent`, ...) — use .NET/engine APIs instead; modules load lazily on first use; oh-my-posh/zoxide init scripts are cached and patched in `%LOCALAPPDATA%\PowerShellProfileCache` (bump the `v6` cache key after changing a `$Generate` block). The patches measurably help (about 300 ms at startup, 30 ms per prompt); a first-prompt prefetch was measured, gained nothing and was removed. Never set `Set-PSReadLineOption -EditMode` below custom key bindings — it resets them. New aliases: a `${alias:name} = 'target'` line in the `#Alias` section, not `Set-Alias`. The `cheat` function is the one list of shortcuts.
- **Elevation**: `Bootstrap.ps1` runs the whole apply elevated, so a setup script must not install a per-user tool by downloading and running its install script (it would run with administrator rights): take it from winget. Bootstrap only pauses at the end in the window it relaunched itself into (`-Relaunched`).
- **User PATH edits**: `HKCU:\Environment\Path` is `REG_EXPAND_SZ` and can contain tokens such as `%USERPROFILE%`, `%NVM_HOME%` and `%NVM_SYMLINK%` (older nvm installers; nvm 2 writes plain paths). Write it with `Set-ItemProperty -Type ExpandString` and read it with `GetValue('Path','','DoNotExpandEnvironmentNames')`. `[Environment]::SetEnvironmentVariable(...,'User')` expands those tokens and bakes them out permanently, breaking the nvm indirection.
- **CI pins**: chezmoi's pin (version and release checksums) is in `lint.yml` and `Scripts/WSLSetup.sh`: bump both together. PSScriptAnalyzer rules are excluded repo-wide only when they can't apply anywhere; a single justified exception is a `SuppressMessageAttribute` on that script (as in `user_profile.ps1`).
